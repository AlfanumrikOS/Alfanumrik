# Super-Admin Orphaned-API Disposition Ledger

**Date:** 2026-08-16
**Status:** Phase 0 of the super-admin mission-control overhaul. See `docs/superpowers/specs/2026-08-16-super-admin-mission-control-design.md` for the full RCA and roadmap this ledger supports.
**Owner:** ops (this ledger) — each disposition's implementation is owned per the "Owner agent" column.
**Method:** Every route below was confirmed present on disk (`find`/`Read`) as of 2026-08-16. "UI callers" was checked with a repo-wide search for the route's literal path string under `apps/host/src/app` (pages + client components); a route with zero hits outside its own implementation files is marked orphaned. This is a static-search check, not a runtime trace — if a route is called only via a dynamically-constructed URL, it will read as orphaned here when it is not. Flag any such case found later back into this table rather than trusting the label blind.

## Disposition legend

- **Wire (Phase N)** — build a UI caller in the named phase. Route stays as-is (or gets a small contract tweak) until then.
- **Delete (Phase 2)** — confirmed superseded or dead; scheduled for removal alongside the Phase 2 console merge, pending a final no-caller re-check at execution time (per `docs/superpowers/specs/2026-08-16-super-admin-mission-control-design.md` §4).
- **Keep curl-only** — intentionally an operator/runbook tool, not a UI candidate (e.g. one-off diagnostics, break-glass operations). Stays unwired by design.
- **Recommend deletion review** — not yet confirmed dead; flagged for an explicit go/no-go decision in the named phase rather than auto-scheduled.

## Notes for Phase 0 execution

The task scope names these as the explicit Phase 0 wires: sessions (force logout), users PATCH (profile + admin_level), and support's `resend_invite`/`fix_relationship`. This ledger also surfaces `reset_password` (same route file, same phase-0-shaped effort) and flags `alerts` and `demo-accounts/[id]/resend-credentials` as candidates ops should confirm in/out before Phase 0 closes — see the "Wire in Phase 0/N" rows above. Do not treat "Phase 0/N" as ambiguous forever; ops must pin a single phase per route before Phase 0 sign-off.

Every "Recommend deletion review" row must get an explicit decision (keep-and-wire, or confirmed-delete) recorded back into this table before the phase named in that row starts — do not let it default to either outcome silently.
