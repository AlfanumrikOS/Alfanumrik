## 11. Principles synthesised for Alfanumrik (not copied from any one)

1. **One shell, one nav model.** A single app shell with a role-specific nav *config* (data), a scope switcher (school → class → student) in the top bar for staff roles, and a five-slot bottom bar on mobile. Five shells and six page-local navbars go.
2. **Every object has one list and one detail.** Students, teachers, parents, classes, chapters, questions, worksheets, quizzes, payments each get exactly one list view (sortable, filterable, paginated, bulk-selectable) and one detail view, reused across roles with RBAC-scoped columns. This collapses the four "people" pages, five money pages and eight health pages.
3. **Search is the nav.** ⌘K / search bar over students, teachers, schools, chapters, questions, worksheets — scoped by role, backed by one server endpoint.
4. **Filter-as-query and saved views** rather than new pages per filter.
5. **Import is a first-class flow**: template download → upload → column mapping → validation preview → commit → error-row report; identical for students, teachers, parents, questions.
6. **Named mastery tokens** (5 levels) rendered identically for student, parent, teacher, school.
7. **Semantic colour only.** Brand colour for identity and primary action; state colours (`success/warning/danger/info` + mastery bands) as tokens; no page-local hex.
8. **Type does more with less**: a 6-step fluid scale, one UI family plus Devanagari fallback; tabular numerals for scores and money.
9. **Four states are part of the component contract** (loading skeleton that matches final layout, empty with one action, inline error with retry, success), never a page-local improvisation.
10. **Mobile-first budget**: ≤48 px touch targets, no JS-gated first paint, hero and above-the-fold content server-rendered and visible without JavaScript.

Assets, mascots, logos, illustrations and layouts from the ten portals are explicitly excluded; only these principles carry into 06-design-system.
